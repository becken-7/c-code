### 1. 练习1：指针加、减一个整数（课件 p38、p39）

**原题**：`short int score[10]={84,65,77,60,88,86,92,93,70,66};`  
图中内存地址：score[0] 在 2000，score[1] 在 2002 …… 每个 `short` 占 2 字节。

| 题目  | 定义                                       | `p++` 后 p 的值          | `p--` 后 p 的值                   |
| --- | ---------------------------------------- | --------------------- | ------------------------------ |
| p38 | `short int *p1; p1=&score[0];`           | **2002**（指向 65）       | **1998**（图中特意标了 `p1-1` 在 1998） |
| p39 | `long int *p2; p2=(long int*)&score[0];` | **2004**（long 占 4 字节） | **1996**（图中 `p2-1` 在 1996）     |

> 课件把 `p++;` 和 `p--;` 当作**两个独立提问**（每行都从初值出发），所以答案是 1998 / 1996；如果理解成"先自增再自减"连续执行，则 p-- 之后都回到 **2000**。答题时把这点写清楚最保险。

**为什么**：`p++` / `p--` 不是让地址加/减 1 个字节，而是加/减 **1 个所指类型的数据单元**，即 `p ± n` 等价于地址 `p ± n × sizeof(*p)`。

- `short*` → 每次移动 2 字节；`long*`（Windows 下 4 字节）→ 每次移动 4 字节；`double*` → 8 字节。

**易错反馈**：

- 最常见的错误答案是把 `p1++` 答成 2001、`p2++` 答成 2001 —— 一定要先看指针的**基类型**。
- p39 里 `p2` 是被强制转换成 `long int*` 的，虽然它实际指向的是一个 `short` 数组，但**指针运算只认它自己的类型**，所以按 4 字节走。这也是后面 6-29 出事的伏笔。
- 别把两行当成"先加再减"的连续操作：连续执行的话 `p--` 只是回到 2000，就考不出"步长"这个知识点了；课件画 `p1-1`/`p2-1` 正是为了让你独立算。

**知识点**：指针的算术运算、指针的基类型与步长、`sizeof`、地址按字节编址、强制类型转换不改变地址值只改变解释方式。

### 2. 练习2：两个指针相减（课件 p40、p41）

| 题目  | 定义                                                                              | 结果    |
| --- | ------------------------------------------------------------------------------- | ----- |
| p40 | `short int *p1,*p2; p1=&score[0]; p2=score+4;` 求 `p2-p1`                        | **4** |
| p41 | `long int *p3,*p4; p3=(long int*)&score[0]; p4=(long int*)(score+4);` 求 `p4-p3` | **2** |

**为什么**：两个同类型指针相减，结果是**它们之间相差的元素个数**，公式为 `(地址差) / sizeof(所指类型)`，类型是 `ptrdiff_t`。

- p40：p1=2000，p2=2008，差 8 字节 ÷ 2 字节 = **4**（就是 score[4] 的下标 4）。
- p41：`score+4` 已经是 2008，强转成 `long int*` 后地址仍是 2008；p3=2000，差 8 字节 ÷ 4 字节 = **2**。

**易错反馈**：第二问最容易照抄第一问答 4。注意 `p4-p3` 的单位是 `long`（4 字节），同样 8 字节的距离只能放 2 个 long。**指针相减的结果跟"指针被声明成什么类型"有关，跟它实际指向什么数据无关。**

**知识点**：指针相减的语义与单位、数组名 `score` 退化为 `&score[0]`、`score+n` 的地址计算、强制类型转换对指针运算的影响。

### 3. 练习3：指向常量的指针做形参（课件 p42）

**问题**："什么情况下你会用指向常量的指针做形参呢？"

**答案**：当函数**只需要读取**传进来的数组/对象，而**不打算修改**它时，就把形参声明为 `const T *`（如 `void print(const int *p, int n)`）。好处有四条：

1. **编译器兜底**：函数体内一旦写了 `*p = ...` 或 `p[i] = ...`，直接编译报错，避免手滑改坏调用者的数据（课件 p15 的编译报错就是例子）；
2. **能接收常量实参**：`const int a[5]` 或字符串字面量只能传给 `const T*`，普通 `T*` 接不了；
3. **表达设计意图**：看函数声明就知道它只读，代码更好维护；
4. **便于优化**：编译器知道数据不会被本函数改写。

典型例子：`strlen(const char*)`、`strcmp(const char*, const char*)`、打印数组、求最大值/平均值（对应课件里 GradeBook 的 `getAverage(const int setOfGrades[], ...)`）。

**易错反馈**：`const int *p` 不是说 p 指向的变量"永远不能改"，只是**不能通过 p 改**；别的非常量指针仍然可以改它。另外别和 `int *const p`（指针本身不能改指向）搞混。

**知识点**：`const` 与指针的三种位置、最小权限原则、const 正确性（const-correctness）、数组形参退化为指针、const 引用替代指针。

### 4. "为什么错了？" 三组 const 指针（课件 p43 Fig8.10 / p44 Fig8.11 / p45 Fig8.12）

| 页   | 声明                            | 出错语句                            | 原因                                                |
| --- | ----------------------------- | ------------------------------- | ------------------------------------------------- |
| p43 | `void f(const int *xPtr)`     | `*xPtr = 100;`                  | `const int*` = **指向常量的指针**，`*xPtr` 是只读的，不能赋值      |
| p44 | `int * const ptr = &x;`       | `ptr = &y;`（但 `*ptr = 7;` 是合法的） | `const` 在 `*` 右边 = **常量指针**，ptr 本身不能再指向别处；所指数据可以改 |
| p45 | `const int * const ptr = &x;` | `*ptr = 7;` 和 `ptr = &y;` 都错    | 数据只读 + 指针只读，两个都不能改                                |

编译器报错：MSVC `error C3892: you cannot assign to a variable that is const`；GNU `assignment of read-only location` / `assignment of read-only variable`。

**记忆口诀**：从右往左读声明 ——

- `const int *p` → p 是指针，指向 `const int`：**数据只读，指针可改**；
- `int * const p` → p 是 const 指针，指向 `int`：**指针只读，数据可改**；
- `const int * const p` → **都只读**。

**知识点**：顶层 const / 底层 const、声明的读法、常量指针与指向常量的指针的区别、编译期保护。

### 5. 练习1：静态局部数组 vs 自动数组（课件 p8、p9）

**问题**："请仔细阅读此程序，分析程序的运行结果！并上机验证你的分析是否正确？"

**答案**（课件 p9 给出的实测结果）：

```
第一次调用：
  进入 staticArrayInit    : array1 = 0 0 0        （静态数组默认零初始化）
  离开 staticArrayInit    : array1 = 5 5 5
  进入 automaticArrayInit : array2 = 1 2 3        （自动数组每次重新初始化）
  离开 automaticArrayInit : array2 = 6 7 8
第二次调用：
  进入 staticArrayInit    : array1 = 5 5 5        ← 保留上一次的结果！
  离开 staticArrayInit    : array1 = 10 10 10
  进入 automaticArrayInit : array2 = 1 2 3        ← 又回到初始值
  离开 automaticArrayInit : array2 = 6 7 8
```

**为什么**：`static` 局部数组存放在静态存储区，**只在第一次执行到定义处时初始化一次**，生存期到程序结束，所以调用之间的值会保留；普通局部（自动）数组在栈上，每次调用函数都重新创建并初始化，函数结束就销毁。

**知识点**：存储类别（static / automatic）、生存期与作用域、静态存储区默认零初始化、初始化只发生一次。

### 6. 练习2：把数组传递给函数（课件 p10~p13、p15）

**问题 A**："数组名 b 做形参，编译器会将其转换为什么类型？编译器为什么这样做？"

**答案**：`void modifyArray(int b[], int size)` 中的 `b` 会被编译器自动转换为 **`int *b`（指向首元素的指针）**，数组形参完全退化为指针，`sizeof(b)` 得到的是指针大小（64 位下 8 字节）而不是数组长度。  
原因：C/C++ 不支持数组整体按值传递（复制整个数组开销大，且 C 语言早期就这样设计），传首地址最高效；代价是函数**无法自己知道数组长度**，所以必须额外传一个 `size` 参数；也正因为传的是地址，函数里 `b[k] *= 2` 会**直接改到 main 中的实参数组 a**。

**问题 B**："分析程序的运行结果"（课件 p13）：

```
原数组                    : 0 1 2 3 4
modifyArray 之后          : 0 2 4 6 8      ← 整个数组被改（传地址）
a[3] before modifyElement : 6              ← 注意 a[3] 已被上一步从 3 改成 6
函数内元素的值             : 12             ← 形参是副本，×3 只改副本
a[3] after modifyElement  : 6              ← 实参没变
```

**问题 C（p15）**：为什么编译报错？因为形参写成了 `const int b[]`，函数里却给 `b[i]` 赋值，触发 `assignment of read-only location` / C3892 —— 这正是练习3 讲的"用 const 保护数组"。

**易错反馈**：最容易错的是以为"数组传参是值传递，函数里改不影响外面"。记住：**数组名作实参 = 传首地址**，唯一按值传递的是 `a[3]` 这种单个元素。

**知识点**：数组名退化为指针、形参 `int b[]` 等价 `int *b`、按值传递 vs 按地址传递、形参数组长度丢失、const 数组形参。

### 8. 【6-17】 未初始化的野指针（课件 p68）

```cpp
int main(){
    int *p;        // 只定义，没初始化
    *p = 9;        // ❌ 向一个随机地址写入
    cout << "the value at p:" << *p;
    return 0;
}
```

**问题**：`p` 是**未初始化的野指针**，它的值是栈上的随机残留值。`*p = 9` 会向一个未知地址写 4 字节，属于**未定义行为**：轻则数据被悄悄破坏，重则立刻段错误 / 访问违规崩溃。

**实测反馈**：g++ `-Wall` 直接给出 `warning: 'p' is used uninitialized`；我这次运行恰好输出 `the value at p:9` 且退出码 0 —— **"能跑出正确结果"纯属运气**，说明这个 bug 有多隐蔽。这也是题目让我们"仔细体会使用指针时应避免出现的问题"的原因。

**改正**：

```cpp
int a;
int *p = &a;     // 让指针指向一块确定的、合法的内存
*p = 9;
// 或者：int *p = new int(9);  ...用完 delete p;
```

**知识点**：野指针 / 悬空指针、定义指针时立即初始化（至少 `= nullptr`）、解引用前确保指向有效对象、未定义行为、编译警告的价值（`-Wall -Wextra`）。

### 9. 【6-18】 内存泄漏（课件 p69）

```cpp
int fn1(){
    int *p = new int(5);
    return *p;            // ❌ p 指向的堆内存没有 delete
}
```

**问题**：`new` 申请的 4 字节堆内存**从未释放**。函数返回后局部变量 p 被销毁，这块内存的地址就永久丢失了，程序再也无法回收它 —— **内存泄漏**。每调用一次漏 4 字节，如果放在循环里调用几十万次，内存占用会持续增长。

**实测反馈**：程序能正常输出 `the value of a is:5`，编译也没有警告（编译器不检查逻辑层面的泄漏）—— 说明**功能正确 ≠ 没有 bug**，这类问题只能靠代码审查或 Valgrind / ASan 等工具发现。

**改正**（两种，第二种更好）：

```cpp
int fn1(){                            // 方案一：成对使用 new/delete
    int *p = new int(5);
    int v = *p;
    delete p;
    return v;
}
int fn1(){ return 5; }               // 方案二：根本不需要动态内存，直接用值
```

**知识点**：堆内存与 new/delete 配对、内存泄漏及其累积效应、RAII、现代 C++ 用 `std::unique_ptr` / 容器代替裸 new。

### 10. 【6-29】 用 reinterpret_cast 绕过类型系统造成安全性问题（课件 p71）

```cpp
int main(){
    int arr[] = {1,2,3};
    double *p = reinterpret_cast<double *>(&arr[0]);
    *p = 5;                                  // ❌ 按 double 写 8 字节
    cout << arr[0] << " " << arr[1] << " " << arr[2] << endl;
    return 0;
}
```

**实测输出（本机 g++，-O0 与 -O2 相同）**：

```
0 1075052544 3
```

**它是怎么造成安全问题的（逐层拆解）**：

1. `reinterpret_cast<double*>` 只是把同一个地址**重新解释**成 double 指针，并不改变内存大小 —— arr 一共只有 3 个 int = 12 字节。
2. `*p = 5;` 写入的是 **double 类型的 5.0，占 8 字节**，从 `&arr[0]` 开始一口气覆盖了 `arr[0]` 和 `arr[1]` 两个 int。
3. double 5.0 的 IEEE754 位模式是 `0x4014000000000000`；小端序下低 4 字节 `0x00000000` → `arr[0] = 0`，高 4 字节 `0x40140000` = 十进制 **1075052544** → `arr[1]` 被改成这个数。`arr[2]` 没被碰到，仍是 3。
4. 更深层：这违反**严格别名规则（strict aliasing）**，且 int 数组只有 4 字节对齐而 double 通常要求 8 字节对齐 —— 属于**未定义行为**，换平台/换编译器结果可能完全不同。
5. 安全意义：通过强制类型转换骗过类型系统，向一块较小的缓冲区写入更大的数据，就是**越界写 / 缓冲区溢出**的雏形；在栈上可能覆盖相邻局部变量甚至函数返回地址，是真实漏洞（如栈溢出攻击）的原理。

**如何避免**：

- 不要在不同类型的指针之间用 `reinterpret_cast` 后**写入**；类型不同就老老实实用值转换（`static_cast<double>(arr[0])`）。
- 确实需要按字节查看对象时，只能用 `char*` / `unsigned char*` / `std::byte*`（标准允许它们别名任何类型），并且确保缓冲区足够大。
- 用 `-Wall -Wextra`、`-fsanitize=address,undefined` 等工具检测越界与未定义行为。
- 优先使用 `std::array` / `std::vector` / `std::span` 这类带边界信息的类型，少用裸数组 + 裸指针。

**知识点**：reinterpret_cast 与类型双关、严格别名规则、内存对齐、越界写与缓冲区溢出、未定义行为、IEEE754 浮点位模式、大小端。

2. **最值得动手验证的三处**：6-17 的野指针（看编译器警告）、6-18 的内存泄漏（功能对但有问题）、6-29 的 `0 1075052544 3`（用浮点位模式解释输出）。这三题光看答案印象不深，自己跑一遍会记住一辈子。
3. **const 是本讲第二个高频考点**：`const int*`、`int* const`、const 数组形参、"为什么错了"三张图其实是同一个知识点的四种问法，建议把口诀抄一遍。
4. **写作业时养成两个习惯**：定义指针立刻初始化；编译一律带 `-Wall -Wextra`。这次 6-17 的警告就是编译器白送的提示。
5. **递归题（6-22、上一讲的 3-13）注意边界**：空串、单字符、n=0，以及递归深度过大导致栈溢出。
